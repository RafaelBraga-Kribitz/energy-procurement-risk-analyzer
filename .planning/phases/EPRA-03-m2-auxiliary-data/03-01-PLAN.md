<objective>
Extend the single raw-parquet writer `_io.write_month()` with an additive, backward-compatible `key_column` parameter so date-grain datasets (GeoSphere daily temperature, §7 `date` key) can reuse the exact ING-003/004 atomic-write path without a second writer and without bending the GeoSphere §7 contract to invent a `ts_utc` column (RESEARCH Pattern 1, Pitfall 1).

Purpose: unblock GeoSphere ingest (03-04) — its §7 contract is `date`-keyed, but `write_month` currently hard-requires a tz-aware UTC `ts_utc` column and raises `ContractError` otherwise.
Output: `write_month(..., *, key_column="ts_utc")` with a validation dispatcher; the `ts_utc` path is byte-identical to today, a new plain-`date` path validates month bounds without tz assertions.
</objective>

<assumption_delta_decision>
This phase adds the SECOND write-key grain (date) where `ts_utc` was previously the ONLY key — a required/only anchor becoming one of several (pluralization + constant→parameter).

- **Primary noun:** the raw write **key column** (was implicitly always `ts_utc`).
- **Decision:** **promote** — parameterize `key_column` with `"ts_utc"` as the default variant. `ts_utc` is demoted from "the only key" to "the default key," not kept as a required assumption. Additive default preserves every M1 caller byte-for-byte (no add-alongside debt).
- **Invariant test (adopted):** `test_io.py` asserts BOTH a `ts_utc`-keyed frame and a `date`-keyed frame round-trip through `write_month` correctly, so a future change that silently reintroduces the "ts_utc is mandatory" assumption goes red immediately.
</assumption_delta_decision>
