# Phase EPRA-03 Plan 04: GeoSphere Daily Temperature Ingest Summary

**GeoSphere klima-v2-1d daily temperature ingest to date-keyed monthly parquet via the extended `_io.write_month`, with a pure `gate_ing_094` validation gate -- fully network-free in CI against committed fixtures.**

## Performance

- **Completed:** 2026-07-23

## Accomplishments

- `parse_geojson` parses the real GeoSphere `klima-v2-1d` GeoJSON response shape (`timestamps[]` parallel to `features[0].properties.parameters.tl_mittel.data[]`) into the SPEC-01 §7 `date, station_id, tl_mittel_c, parameter_raw` frame, validating the top-level shape before any nested indexing so a mis-parse raises `ContractError` rather than silently returning an empty frame
- `_fetch_geosphere` + `ingest` implement the full ING-093 ingest path: no-auth GET with an on-disk `data/cache/geosphere/` cache (ING-009's 7-day rule) and a `>=0.2s` politeness sleep after live fetches only, writing one parquet per calendar month through `_io.write_month(..., key_column="date")` -- the 03-01 date-key extension, reusing the shared writer rather than a second one
- `gate_ing_094` extends `validate.py`'s `GateResult`/`ValidationReport` framework: coverage `>=99%` of calendar days spanned by the data itself (not an hours-based constant), `[-30, 42]` degC range, July mean `[15, 30]`, January mean `[-10, 8]`, with a passing case and a failing case for every check
- CLI `main()` (`python -m epra.ingest.geosphere [--start] [--end]`), a `make geosphere` target, and a `geosphere_graz_daily` date-keyed row in `tests/test_raw_contracts.py` (the ts_utc/zone-specific contract assertions now generically skip date-keyed datasets)

## Decisions Made

- `parameter_raw` stores the raw JSON literal (`json.dumps(v)`) of each `tl_mittel` value as provided by the API, distinct from the float64-coerced `tl_mittel_c` -- preserves wire fidelity for audit (matches the SPEC-01 §7 `parameter_raw json/varchar` column type)
- `gate_ing_094`'s coverage denominator is the calendar-day span the ingested data itself covers (`min(date)..max(date)`, inclusive), never an hours-based constant copied from the ENTSO-E gates (RESEARCH Pitfall 6 -- confirmed the wrong denominator would silently report near-100% coverage on a badly-gapped window)
- `_fetch_geosphere` is a small, GeoSphere-scoped transport function with its own cache/politeness logic rather than forcing GeoSphere through `_fetch.fetch_entsoe`, which is typed around `EntsoeQuery`/`EntsoeRawClient` (ADR-003) -- matches the RESEARCH "Alternatives Considered" recommendation
- `main()`'s `--start`/`--end` are both optional, defaulting to `settings.window.start_date`/today, so a bare `make geosphere` invocation (matching `make ingest`/`make backfill`'s no-required-date-args ergonomics) ingests the full 2019-latest window
- The committed `geosphere_graz_daily_2024-01.parquet` contract fixture was generated by running the real `parse_geojson` + `write_month(key_column="date")` path against the committed `klima_2019-01.geojson` fixture, then remapping the January dates from 2019 to 2024 (temperature/station/parameter values untouched) solely to follow this repo's existing `<dataset>_2024-01.parquet` naming convention -- the same "no committed real source at this exact vintage" precedent already established for `entsoe_prices_delu`'s hand-built fixture
