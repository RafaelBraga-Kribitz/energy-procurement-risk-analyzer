# 01 — PHASES: Roadmap, entry/exit criteria, rollback

Phases map 1:1 onto Charter §7 milestones (the Charter's build order is
mandatory for merges; the M2↔M1 merge swap is sanctioned by R-1 — see
[00_MASTER_PLAN.md](00_MASTER_PLAN.md) §0.4). Effort budgets are Charter §7's;
exceeding 2× budget triggers a blocker ADR before continuing.

**Rollback rule (all phases):** `main` is always green. A milestone PR that
fails a gate post-merge is reverted as one commit (`git revert -m 1`), the
failure is reproduced on a branch, root-caused, and re-merged. Data artifacts
are never "hot-fixed" on main; they are regenerated by pipeline code.

## Phase 2 — Core ingestion (M1)

- **Goals:** all four ENTSO-E datasets, 2019 → latest complete month, cached,
  validated, contract-tested.
- **Entry criteria:** token live (TP.01); T1.01–T1.08 code complete on branch;
  M2 merged (for the calendar used by DST validation checks).
- **Exit criteria / quality gates:** ING-070 contract tests green on committed
  fixtures; ING-080..085 green on real 2019→latest data; validation report
  committed; SG-01/SG-02 ADRs merged.
- **Deliverables:** `ingest/entsoe.py`, `ingest/validate.py` (full), fixtures
  from real pulls (≤200 rows each), `make backfill|ingest|validate-ingest` live.
- **Rollback condition:** ING-082 annual-mean gate failure (most likely unit or
  TZ bug) — do NOT widen; revert/fix per the guide's investigation protocol.

## Phase 3 — Warehouse (M3)

- **Goals:** dbt staging + dim_calendar + marts + tests; CI fixture build.
- **Entry criteria:** M1 + M2 merged (real raw parquet exists locally); SG-06,
  SG-13 resolved by ADR.
- **Exit criteria / quality gates:** `dbt build` green on real data AND on
  fixtures in CI (EN-080 job 3 added and required); mart schemas byte-match the
  committed contract YAML (DM-060..066 all pass).
- **Deliverables:** models per SPEC-02 §§3–5, contract YAML + schema test,
  fixture bootstrap script, CI job 3.
- **Rollback condition:** schema contract diff after merge, or DM-064
  reconciliation drift > 0.01.

## Phase 4 — Consumer profile (M4)

- **Goals:** deterministic hourly load for styriametal_v1 + flat_baseload,
  covering analysis + forward windows; monthly volumes; peak share.
- **Entry criteria:** M3 merged (`dim_calendar` queryable); SG-03/SG-04 ADRs.
- **Exit criteria / quality gates:** LP-040 golden (incl. checksum), LP-041
  property, LP-042 meta-test green; annual sums = 50,000.00 ± 0.01;
  `consumer_peak_share` lands in SSOT inputs.
- **Deliverables:** `consumer/profile.py`, `make profile`, processed parquet ×2,
  `fct_consumer_load_hourly` enabled in dbt.
- **Rollback condition:** checksum instability across two clean runs (LP-001
  violated) — fix before ANY other work (A-4).

## Phase 6 — Strategies (M6)

- **Goals:** anchors → retrospective matrix → sensitivities → forward bootstrap →
  SSOT generation + consistency checker.
- **Entry criteria:** M5 merged (regime labels for no-crisis variant); ÖSPI
  covers window; SG-07/SG-08/SG-09 ADRs.
- **Exit criteria / quality gates:** ST-601 golden, ST-602 sanity relations
  (a/b/c), ST-603 determinism + no-lookahead, ST-604 SSOT consistency; CI job 4
  (ssot-check) added and required.
- **Deliverables:** three strategy modules, `scripts/generate_ssot.py`,
  `scripts/check_ssot_consistency.py`, `make simulate|ssot`, goldens.
- **Rollback condition:** ST-602(a) failure = broken ÖSPI translation — halt,
  debug calibration first (per SPEC-05 §9); never rationalize.

## Phase 7 — Reporting, dashboard, release (M7)

- **Goals:** exports, executive charts, EXEC_SUMMARY, final README/LIMITATIONS,
  refresh cron, Power BI handoff + human build, release.
- **Entry criteria:** M6 merged; SSOT populated; GitHub remote + secret exist (TP.02).
- **Exit criteria / quality gates:** Charter §6 **DL-1…DL-10 all green** — the
  release gate; every item ticked in the PR description with evidence
  ([11_ACCEPTANCE_CRITERIA.md](11_ACCEPTANCE_CRITERIA.md) §M7).
- **Deliverables:** `scripts/export_marts.py`, `report/charts.py`,
  `reports/EXEC_SUMMARY.md`, `refresh.yml`, `dashboards/` complete, screenshots.
- **Human dependency:** `.pbix` build + screenshots; EXEC_SUMMARY §5 co-write.
- **Rollback condition:** GV-303 consistency failure on main, or refresh dry-run
  failure — release is blocked until green.

## Post-release operations (steady state)

Monthly: `refresh.yml` (EN-081..083) opens an automated PR with regenerated
reports; human merges after checking the ING gates summary and ÖSPI coverage
note. Quarterly: dependency-bump PR (pins changed only via ADR, GV-203).
